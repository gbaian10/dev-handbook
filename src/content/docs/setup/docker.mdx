這頁在 Ubuntu 裡安裝 Docker Engine，適用 Ubuntu 桌面（`desktop`）、Windows 上的 WSL（`wsl`）與個人遠端伺服器（`personal-server`）。共用伺服器（`shared-server`）由管理員安排容器環境。

|          | Docker Engine（這頁的做法）  | Docker Desktop                               |
| -------- | ---------------------------- | -------------------------------------------- |
| 跑在哪裡 | Ubuntu 本身，由 systemd 管理 | Windows 上的另一個程式，WSL 透過整合功能借用 |

WSL 需使用 WSL 2 並啟用 systemd。在 PowerShell 用 `wsl --list --verbose` 確認發行版的版本為 2，再在 WSL 的 Ubuntu 執行 `ps -p 1 -o comm=`，確認第一個程序是 `systemd`。需要啟用時，依 [Microsoft 的 WSL systemd 說明](https://learn.microsoft.com/en-us/windows/wsl/systemd)設定。

:::note[需要 sudo 的步驟]
這頁的安裝指令都要 sudo，自己在終端機執行。
:::

<Steps>

1. **安裝 Docker Engine**

   官方說明：[Install Docker Engine on Ubuntu](https://docs.docker.com/engine/install/ubuntu/)

   已有容器環境時，先逐一檢查可能衝突的套件。確認其他服務沒有依賴這些套件後，再用 `sudo apt remove` 加上要移除的套件名稱。新裝的系統若沒有任何相關套件，直接加入 Docker 的套件庫。

   ```bash
   dpkg -l docker.io docker-compose docker-compose-v2 docker-doc docker-buildx podman-docker containerd runc
   ```

   加入 Docker 官方的 apt 套件庫：

   ```bash
   sudo apt update
   sudo apt install ca-certificates curl
   sudo install -m 0755 -d /etc/apt/keyrings
   sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
   sudo chmod a+r /etc/apt/keyrings/docker.asc

   sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
   Types: deb
   URIs: https://download.docker.com/linux/ubuntu
   Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
   Components: stable
   Architectures: $(dpkg --print-architecture)
   Signed-By: /etc/apt/keyrings/docker.asc
   EOF

   sudo apt update
   ```

   安裝：

   ```bash
   sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
   ```

   這裡採用 Docker 官方套件庫，Engine、Buildx 與 Compose 外掛可由同一來源安裝及更新。
   Ubuntu 上 Docker 預設開機自動啟動，不用另外 `systemctl enable`。

   確認：

   ```bash
   sudo docker run --rm hello-world   # 印出 Hello from Docker!
   ```

2. **不用 sudo 就能跑 docker**

   這一步可選。保留預設權限時，繼續用 `sudo docker` 執行後面的指令。

   官方說明：[Linux post-installation steps](https://docs.docker.com/engine/install/linux-postinstall/)

   ```bash
   getent group docker || sudo groupadd docker
   sudo usermod -aG docker "$USER"
   ```

   :::caution[docker 群組等於 root]
   能用 docker 就能用容器掛載整個系統、以 root 身分改任何檔案。只把自己加進去，不要加共用帳號。
   :::

   要立刻使用新的群組，執行 `newgrp docker` 開一個子 shell。Ubuntu 桌面要登出桌面工作階段再登入，遠端伺服器要中斷 SSH 再連線。WSL 若開新分頁後仍缺少群組，儲存工作後在 PowerShell 用 `wsl --terminate <發行版名稱>` 停掉該發行版，再開新分頁。

   確認：

   ```bash
   id -nG | grep -w docker      # 有印出 docker
   docker run --rm hello-world  # 不加 sudo 也能跑
   ```

   若收到 Docker socket 的 `permission denied`，先用 `id -nG` 檢查目前的工作階段是否已取得 `docker` 群組。

3. **顯示卡驅動**

   沒有 NVIDIA 顯示卡的機器，到這裡就結束了。

   <Tabs syncKey="machine">
   <TabItem label="WSL">
   **驅動裝在 Windows 上，WSL 裡什麼都不用裝。** Windows 的 NVIDIA 驅動會把 GPU 函式庫放在 WSL 的 `/usr/lib/wsl/lib`，WSL 直接用這份。要更新驅動也是在 Windows 上更新。

   :::danger[不要在 WSL 裡裝 Linux 版 NVIDIA 驅動]
   會蓋掉 Windows 提供的那份，GPU 反而用不了。
   :::

   確認（`nvidia-smi` 不一定在 PATH 裡，所以寫完整路徑）：

   ```bash
   /usr/lib/wsl/lib/nvidia-smi   # 印出顯示卡型號與驅動版本
   ```

   官方說明見 [NVIDIA 的 CUDA on WSL 指南](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)。

   </TabItem>
   <TabItem label="桌面">
   用 Ubuntu 的工具自動挑選並安裝建議的驅動，裝完重開機：

   ```bash
   sudo ubuntu-drivers install
   sudo reboot
   ```

   官方說明：[Ubuntu：Install NVIDIA drivers](https://documentation.ubuntu.com/server/how-to/graphics/install-nvidia-drivers/)

   確認：

   ```bash
   nvidia-smi   # 印出顯示卡型號與驅動版本
   ```

   :::caution[待實機確認]
   這段還沒在桌面版實際做過，確認後再更新。
   :::
   </TabItem>
   <TabItem label="伺服器">
   先跑 `nvidia-smi`。若能列出顯示卡型號與驅動版本，可進到下一步。若未安裝驅動，依主機供應商的文件或 [Ubuntu 的伺服器驅動說明](https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/)選擇合適的驅動。
   </TabItem>
   </Tabs>

4. **讓 Docker 用得到 GPU：NVIDIA Container Toolkit**

   官方說明：[Installing the NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)

   它負責在容器啟動時，把主機的 GPU 函式庫與裝置接進容器。容器裡不用裝驅動。

   ```bash
   sudo apt-get update && sudo apt-get install -y --no-install-recommends \
      ca-certificates \
      curl \
      gnupg

   curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg \
     && curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
       sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
       sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

   sudo apt-get update
   sudo apt-get install -y nvidia-container-toolkit
   ```

   和官方的差異在於 Ubuntu 26.04 直接安裝 `gnupg` 以取得 `gpg` 指令。`gnupg2` 是過渡套件。這裡也省略官方範例的版本鎖定，讓 apt 安裝 `nvidia-container-toolkit` 及相依套件，之後由 `apt upgrade` 更新。 [Ubuntu 的 GnuPG 套件](https://packages.ubuntu.com/resolute/gnupg)

   設定 Docker 使用 nvidia runtime（會寫入 `/etc/docker/daemon.json`），再重啟 Docker：

   ```bash
   sudo nvidia-ctk runtime configure --runtime=docker
   sudo systemctl restart docker
   ```

   確認：

   ```bash
   nvidia-ctk --version
   sudo docker info | grep -i runtimes
   # Runtimes: io.containerd.runc.v2 nvidia runc

   sudo docker run --rm --runtime=nvidia --gpus all ubuntu nvidia-smi
   # 印出跟主機一樣的 nvidia-smi 表格，看得到顯示卡型號
   ```

</Steps>

## WSL 要注意的地方

- **Docker Desktop 整合**：Windows 上若也裝了 Docker Desktop，請在 Docker Desktop 的設定中關閉這個發行版的 WSL integration，避免兩套 Docker CLI 或 daemon 設定互相干擾。兩個 Engine 各自管理映像、容器與 volume。 [Docker Desktop 的 WSL 整合](https://docs.docker.com/desktop/features/wsl/)
- **連接埠**：Windows 與 WSL 的轉送行為取決於 NAT 或 mirrored 網路模式。兩套容器都要從 Windows 存取時，為它們選不同的主機連接埠。 [Microsoft 的 WSL 網路說明](https://learn.microsoft.com/en-us/windows/wsl/networking)
